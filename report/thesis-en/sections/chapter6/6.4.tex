\section{Operation Monitoring}
\label{sec:6.4}

\paragraph{Technical logs.} The application server and the background worker write logs as JSON, one event per line, automatically tagged with the correlation identifiers of the context: the request identifier for the application server; the job identifier, camera identifier and AI configuration version for the background worker. From the \emph{lookup code} in an error message in the interface (Section~\ref{sec:6.3.2}) or the identifier of a failed job, all related log lines can be filtered out. Before writing, a filter replaces the values of sensitive fields, such as passwords, session tokens, RTSP addresses, feature vectors, images or query sentences, with \texttt{[REDACTED]}, and masks credentials, vector-like number sequences or encrypted data embedded in free text.

\paragraph{Audit log.} Important user actions and technical events of operational significance are stored in PostgreSQL as 32 event types, including logins and session expiry, management of accounts, cameras and AI configuration, processing errors and AI check errors, jobs, cases and data maintenance tools. The Administrator consults them on the \emph{Audit log} screen, filtering by date range, event type, actor and outcome.

\paragraph{Metrics and system status.} While running, each job updates its metrics about every 2 seconds, such as the frame processing rate, the average time of the Detector, Tracker and encoder, memory and CPU usage; the background worker sends a heartbeat every 10 seconds and is considered down if it has been silent for more than 45 seconds. The \emph{System status} screen (Figure~\ref{fig:ui-status}) aggregates this information: for each camera, its RTSP connection status, AI processing status, processing rate and latency, and the number of failed jobs in 24 hours, with the camera placed in one of four groups (normal, offline, AI processing error, unknown); for the components, the health of the three data stores, the search encoder and the job queue. Each piece of information is shown with its age, so that an old number is not mistaken for the current state.
